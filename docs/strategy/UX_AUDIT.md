# UX_AUDIT — Virelle

**Дата:** 2026-07-12  
**Аудитория:** женщины, премиальное бельё и пижамы (RU)  
**Модель:** гибрид — эмоциональный опыт на сайте, заказ v1 во ВКонтакте  
**Вопрос аудита:** что чувствует женщина? что мешает купить? где теряется доверие и премиум?

---

# Метод

Оцениваем путь желания, не отдельные виджеты:

```
Первое впечатление → интерес к коллекции → выбор → уверенность в размере/качестве → действие (VK)
```

# Home (главная)

## Что чувствует

- На hero: «это бренд, красиво, женственно» — brand signal работает
- Ниже: набор секций магазина (сетка, категории, отзывы) — атмосфера бутика слабеет
- Общее: привлекательный лендинг, но не editorial lookbook

## Что мешает купить

- Desire path размыт: много равных блоков без ясного «следующего шага»
- 8 карточек на лендинге могут не совпадать с каталогом (имена/цены) → когнитивный диссонанс
- CTA «Заказать во ВКонтакте» ведёт на `vk.com/feed` — ощущение незавершённости
- Нет моста «коллекция → история изделия → заказ»

## Где теряется доверие

- Placeholder VK
- Mock product photography (uxpilot CDN)
- Нет ясных обещаний по доставке/возврату/уходу на главной (только общие value props)

## Где нет премиального ощущения

- После hero — стандартный ecommerce rhythm (grid + badges)
- Возможный motion-шум (gradient text / badge energy) читается как DTC-шаблон
- Whitespace и typography hierarchy не доведены до editorial

## Рекомендации (Phase 3 TASK 020)

1. Сохранить hero budget: бренд + одна фраза + один CTA-кластер
2. Усилить путь: категории/коллекции → catalog с query → (будущий) PDP
3. Слить/урезать шумные секции; один job на блок
4. Синхронизировать featured products с единым product data

# Catalog (каталог)

## Что чувствует

- «Здесь можно выбрать» — функционально понятно
- Одновременно: «я в админке фильтров», не в бутике

## Что мешает купить

- Нет страницы товара — Quick View слишком мелкий для премиум-решения
- Плотные toolbar / sidebar / modal / pagination = friction без эмоциональной награды
- Холодные gray UI-тексты ломают тёплый бренд
- Размерная уверенность отделена (модалки), не вшита в выбор товара

## Где теряется доверие

- Карточки с ограниченным описанием
- Нет shareable ссылки на конкретный SKU
- Несогласованность данных с главной

## Где нет премиального ощущения

- Dashboard density
- Marketplace hover (image scale)
- Filter UI как SaaS, не как boutique

## Рекомендации (TASK 021)

1. Снизить chrome: quieter filters, больше воздуха в сетке
2. Карточка → ведёт на PDP (primary); Quick View = teaser
3. Заменить gray UI на warm semantic tokens
4. Показывать материал / короткий emotional line на карточке

# Quick View

## Что чувствует

Любопытство, быстрый взгляд — ок как тизер.

## Что мешает купить

Не хватает: материалов, ухода, размерной помощи, галереи, доверия.  
CTA сразу в VK без «я поняла, что беру».

## Рекомендации (TASK 032)

Quick View = preview + «Подробнее» → PDP.  
Заказ из QV допустим, но secondary.

# Product page (PDP) — отсутствует

## Что чувствует сейчас

Пустота после интереса — обрыв истории.

## Почему критично для премиума

Премиальное бельё покупают через **эмоцию + уверенность в посадке/ткани**. Без PDP нельзя:

- рассказать материал и силуэт
- помочь с размером
- дать SEO/шаринг
- собрать favorites вокруг конкретного изделия

## Целевой опыт (TASK 022)

Женщина должна почувствовать: «это про меня, качество видно, размер я подберу, заказать спокойно во VK».

Состав v1: gallery, name, price, materials, care, size CTA (guide/calculator), primary CTA → VK, secondary → favorites.

# Checkout (VK v1)

## Что чувствует

Уход с брендового сайта во внешнюю соцсеть — тревога («куда я попала?»).

## Что мешает

- `vk.com/feed` — не группа бренда → максимальная потеря доверия
- Нет copy «что будет дальше» (написать менеджеру, примерка, оплата)

## Где теряется доверие

Обрыв бренда в момент решения.

## Рекомендации (TASK 005 + 030)

1. Реальный URL группы / сообщения бренда
2. На сайте: короткий trust strip перед уходом (доставка, обмен, как заказать)
3. На PDP: «Оформить во ВКонтакте» + 1 строка ожидания

Cart/Checkout on-site — **вне горизонта** до стабилизации PDP + VK v1.
